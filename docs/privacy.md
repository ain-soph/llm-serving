# 公开仓库与隐私

本仓库从明确选定的源文件和模板建立全新 Git 历史，不导入工作目录的旧历史。部署目录 `~/llm-serving` 就是它的工作树，同一棵树里的本机私有文件靠两道闸挡在库外：`.gitignore` 默认忽略一切、只放行 [`public-paths.txt`](../public-paths.txt) 列出的路径；pre-commit／pre-push 钩子（`tools/git-hooks/`）在每次提交和推送前运行下面的检查器。

纳入：自写 API 包装器、线上 llama-swap／网关配置（本机路径写成环境变量）、模板、安装与校验工具、依赖锁、引擎源码 commit 和不包含本机路径的部署说明。

排除：真实凭证、环境文件、用户目录路径、个人域名、局域网地址、原始部署日志、聊天/请求记录、媒体文件、活动数据库、评测数据、虚拟环境、模型权重、客户端与其他机器的配置。例外：MCP 服务的代码（`clients/mcp/server.py`、依赖、Dockerfile、测试客户端）公开，默认值都指向本机，部署参数和令牌只走环境变量；它的部署文件（compose、env）和各客户端的配置脚本不公开，接法写在 [docs/clients.md](clients.md)。多 agent 分工规则和本地 worker（`platform/agent-bridge/`）也公开：只含代码、模板和 `~` 开头的路径，运行状态、日志和 key 被忽略。回归测试的黄金输出也不提交，每台机器自己录制。运行状态和生成配置放在被 Git 忽略的位置。

Git 提交使用公开 GitHub 用户名及账户的 noreply 邮箱。该 GitHub 账户身份是仓库归属的一部分；模型名、软件版本和目标硬件配置也是有意公开的项目资料。

发布前对 Git 暂存区执行 `tools/privacy_check.py`，并检查提交元数据。检查器读取 index 中的实际文件，不仅依赖 `.gitignore`；检测常见密钥格式、带认证的 URL、个人目录、邮箱、内网地址和不应发布的文件类型。可通过本地的 `--private-literals-file` 加入实际凭证、用户名或域名来检查，命中时只打印规则名和文件名。

自动扫描不是对所有可能个人信息的数学证明，因此还需要逐项核对提交文件清单和人工复核差异。第三方 fork 的既有公开历史不复制进本仓库；此处记录的提交仍链接到原有公开项目。

代码使用 MIT 许可；第三方引擎、依赖和模型遵循各自许可证。本仓库不重新分发模型权重。
