# 零拷贝与 W8A8 副本（重排、Qwen3 嵌入、Decider）

`shared/common/` 是这三类模型共用的模块：

| 文件 | 内容 |
| --- | --- |
| `shared/common/mlx_w8a8.py` | W8A8 线性层（256 宽 Hadamard 旋转 + 按行 INT8 权重与激活，M5 TensorOps INT8 GEMM）；页对齐 safetensors 的写入（`save`）和零拷贝读取（`load`），调用 MLX fork 的 `mx.save_safetensors(page_align=True)`／`mx.load(zero_copy=)` |
| `shared/common/qwen3_w8a8.py` | 把 mlx_lm Qwen3 骨干（重排、嵌入）写成零拷贝、W8A8 或按层类混合（`mix`，带 `mix.json`）目录；`load()` 认三种目录 |
| （内核） | 旋转量化与 INT8 TensorOps GEMM 已并入 MLX fork（`mx.fast.convrot_*`，GEMM 来自 mlx-serve，MIT）；本仓库、mflux、h3-image-mlx 不再各留一份 |
| `shared/common/w8a8_selftest.py` | 层误差、零拷贝逐位读取、GEMM 速度自检 |

W8A8 内核用 M5 的 Metal TensorOps INT8 指令；其他机型未验证。2026-11-17 修了最后一个不满分块的越界读（激活行补齐到 128 的倍数，最后一列分块移回权重内部；比一个列分块还窄的矩阵改走浮点乘），输出逐字节不变；这个修复也随内核一起并入了 MLX fork。数据见[性能报告](performance.md)。

**原则：W8A8 只用在能提速的地方。** INT8 激活带来额外误差，只有在实测确实变快的层或模型上才换；小矩阵（0.6B 重排、
0.6B 嵌入、voyage）、只跑一次或占比很小的阶段（例如 Qwen-Image 的文本编码器）保持 BF16／FP16。只为省内存的权重量化
（Q8_0 等）是另一回事，要单独说明理由。2026-11-18 起一个模型一个入口：按层类选好精度后存成预量化混合副本，不再另设 `-int8` 入口。

### 逐类检查标准

每个量化入口都按投影类别（q/k/v、o、gate/up、down、线性注意力 in_proj / out_proj 等）逐类决定，不整模型一刀切：

1. 先看端到端提速；再逐类测这一类自己快多少、换回浮点后端到端多出多少时间（它在提速里的占比）。
2. 逐类单独换回浮点（或换回只量化权重），用大样本的平均误差和排序（几百到上千对，不只看十几条用例的最大值）看误差来自哪一类。
3. 不提速的类保持浮点；提速很小、但误差占大头的类也换回浮点。组合之间误差不可加，最终组合要整体实测。
4. 只为省内存的权重量化（Q8_0、8-bit）是另一个理由，不受此约束。

服务里的开关：

| 服务 | 参数 | 作用 |
| --- | --- | --- |
| `services/rerank/server.py`、`services/embedding/qwen3/server.py` | `--model <mix 目录>` | 读 `mix.json` 记录的每类精度，零拷贝映射（线上用法）；评测时也可用 `--w8a8-classes ... --float-model <zc 目录>` 临时组合（`load_mixed`） |
| `services/decisions/decider/server.py` | `--w8a8 --w8a8-names ...` | Decider 只量化列出的投影（默认全部 `W8A8_NAMES`） |
| `services/decisions/jev/server.py` | `--quant w8a8 --w8a8-skip ...` | 列出的类保持 8-bit 只量化权重 |

当前结果（重排、嵌入见第 3 节）：Decider 的 `down_proj` 用 FP16；elephant-1 的 `in_proj_z`、mammoth-1 的 `out_proj` 保持 8-bit；
重排／嵌入 8B、Qwen-Image DiT、H3 图片与视频的 DiT 线性层每类都提速、误差分散，全部保留 W8A8。数据见[性能报告](performance.md)。

**W8A16（8 位权重 + 16 位激活）**：激活不量化，只有权重舍入误差，单独对一层或一个模型用没有问题（Qwen-Image 文本编码器
改为 W8A16：误差接近 BF16，硬盘少 5.5 GB，速度持平）。但在其他层已经是 W8A8 的模型里，`down_proj` 要保持原精度：它的输入
已带着前面层的 INT8 激活误差，再加权重舍入会放大（Decider 0.0009 → 0.0617、1 题翻转），而且 W8A16 也不提速。
`shared/common/mlx_q8.py` 与服务的 `--q8-classes`（重排、嵌入）、`--q8-names`（Decider）提供这种选项，默认不启用。
MLX 8-bit 的 scale 要与激活同 dtype（BF16 激活配 FP16 scale 会走慢路径）；精度只能在 GPU 上测（CPU 路径按 scale 的 dtype 计算）。

## 1. 源权重（MLX 格式）

| 模型 | 源目录 | 生成方式 |
| --- | --- | --- |
| Qwen3-Reranker 0.6B / 4B | `qwen3-reranker/mlx-{0.6b,4b}-bf16` | `mlx_lm.convert --hf-path Qwen/Qwen3-Reranker-4B --mlx-path ... --dtype bfloat16` |
| Qwen3-Reranker 8B | `qwen3-reranker/mlx-8b-q8_0` | `services/rerank/q8_0_to_mlx.py HF_DIR OUT_DIR --act-dtype float16`（见 [rerank.md](rerank.md)） |
| Qwen3-Embedding 0.6B / 4B | `qwen3-embedding/mlx-{0.6b,4b}-fp16` | `services/embedding/qwen3/convert_embed.py HF_DIR OUT_DIR --fp16` |
| Qwen3-Embedding 8B | `qwen3-embedding/mlx-8b-q8_0` | `services/embedding/qwen3/convert_embed.py HF_DIR OUT_DIR --q8_0` |
| voyage-4-nano | `voyage-4-nano/mlx-fp16` | `services/embedding/qwen3/convert_embed.py HF_DIR OUT_DIR --fp16` |

HF_DIR 是 `hf download Qwen/Qwen3-Reranker-4B` 等下载的官方目录；转换都在 CPU 上运行。

## 2. 零拷贝副本

同样的权重重写为一个页对齐的标准 safetensors，加载时直接从页缓存映射，数值与源目录完全相同。

```sh
PY=.venv/bin/python; M="$HOME/models"     # 换成实际的模型目录
$PY shared/common/qwen3_w8a8.py rerank "$M/qwen3-reranker/mlx-0.6b-bf16" "$M/qwen3-reranker/zc-0.6b-bf16" --float
$PY shared/common/qwen3_w8a8.py rerank "$M/qwen3-reranker/mlx-4b-bf16"   "$M/qwen3-reranker/zc-4b-bf16"   --float
$PY shared/common/qwen3_w8a8.py rerank "$M/qwen3-reranker/mlx-8b-q8_0"   "$M/qwen3-reranker/zc-8b-q8_0"   --float
$PY shared/common/qwen3_w8a8.py embed  "$M/qwen3-embedding/mlx-0.6b-fp16" "$M/qwen3-embedding/zc-0.6b-fp16" --float
$PY shared/common/qwen3_w8a8.py embed  "$M/qwen3-embedding/mlx-4b-fp16"   "$M/qwen3-embedding/zc-4b-fp16"   --float
$PY shared/common/qwen3_w8a8.py embed  "$M/qwen3-embedding/mlx-8b-q8_0"   "$M/qwen3-embedding/zc-8b-q8_0"   --float
# voyage-4-nano 改回 BF16：FP16 激活在部分 300 token 以上的输入上溢出（NaN 向量）
$PY shared/common/qwen3_w8a8.py embed  "$M/voyage-4-nano/mlx-fp16"        "$M/voyage-4-nano/zc-bf16"        --float --dtype bfloat16
```

- 重排副本只保留输出头里 "yes"/"no" 两行（服务只读这两行）。
- 生成后源目录 `mlx-*` 不再被服务读取，可以删除（本机多数已删）；需要重新生成时从官方权重重新下载并转换。
- 嵌入 0.6B／4B、voyage 的线上入口直接用 `zc-*`；重排三种尺寸和嵌入 8B 的 `zc-*` 只是第 3 节混合副本的输入，生成后可以删除。

## 3. 按层类混合副本（重排三种尺寸、嵌入 8B）

2026-11-18（pa1b）起，原来的“精确 + `-int8`”两个入口合并为一个入口，每个模型一份按层类选精度的预量化副本：
`shared/common/qwen3_w8a8.py mix` 读第 2 节的零拷贝副本，按计划替换各类投影，写出一个页对齐 `model.safetensors` 和记录计划的
`mix.json`；服务端 `load()` 见到 `mix.json` 就按它零拷贝映射，不需要额外参数。计划写法：`qkv`、`o`、`gateup`、`down`
各取 `w8a8`（INT8 权重与激活）、`w8a16`（8 位权重、浮点激活）或 `float`（保持源精度；源本身是 Q8_0 时即 8 位权重）。

```sh
$PY shared/common/qwen3_w8a8.py mix rerank "$M/qwen3-reranker/zc-0.6b-bf16" "$M/qwen3-reranker/mix-0.6b" qkv=w8a8,o=w8a8,gateup=w8a8,down=float
$PY shared/common/qwen3_w8a8.py mix rerank "$M/qwen3-reranker/zc-4b-bf16"   "$M/qwen3-reranker/mix-4b"   qkv=w8a8,o=w8a8,gateup=w8a8,down=float --dtype float16
$PY shared/common/qwen3_w8a8.py mix rerank "$M/qwen3-reranker/zc-8b-q8_0"   "$M/qwen3-reranker/mix-8b"   qkv=w8a8,o=w8a8,gateup=w8a8,down=w8a8
$PY shared/common/qwen3_w8a8.py mix embed  "$M/qwen3-embedding/zc-8b-q8_0"  "$M/qwen3-embedding/mix-8b"  qkv=w8a8,o=w8a8,gateup=w8a8,down=float
```

| 入口 | 目录 | 每类精度 | 激活 |
| --- | --- | --- | --- |
| `qwen3-reranker-0.6b` | `qwen3-reranker/mix-0.6b` | q/k/v、o、gate/up W8A8，down BF16 | BF16 |
| `qwen3-reranker-4b` | `qwen3-reranker/mix-4b` | q/k/v、o、gate/up W8A8，down FP16 | FP16 |
| `qwen3-reranker-8b` | `qwen3-reranker/mix-8b` | 全部 W8A8（与原 8B W8A8 副本数值相同） | FP16 |
| `qwen3-embedding-8b` | `qwen3-embedding/mix-8b` | q/k/v、o、gate/up W8A8，down 8 位权重（Q8_0 原样） | FP16 |

- 嵌入 0.6B／4B、voyage 保持 16 位：主要流量是单个短查询（约 36 token），这时 W8A8 和 MLX 8-bit 矩阵乘都比 16 位慢。
- 混合副本的转换在 CPU 上做（`load(copy=True)` 后替换），不需要 GPU；`mix.json` 记录源目录名、计划、组大小和激活精度。
- 嵌入 8B 的向量与原 Q8_0 入口不同，换副本后要重建索引；其余嵌入入口不变。
- 原来的 `w8a8-*` 目录和 `--w8a8-classes` 入口参数已不再用于线上入口；`shared/common/qwen3_w8a8.py rerank|embed SRC DST`（不带 `--float`）仍可写出全 W8A8 副本，供评测对比。

## 4. Perplexity Decider（`pplx-decider-flash`）

`services/decisions/decider/save_mix.py` 读官方 BF16 权重的同时把选定的语言模型投影量化为 W8A8，存成预量化副本（2026-11-18 起唯一入口；原 `-int8` / `-multimodal` 入口已并入）。
权重准备见 [decisions.md](decisions.md)。
