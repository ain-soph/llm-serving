**我们的修改：Strata `--prefill auto` 修复**（fork 分支 `serving`）

| 对照 | 修改前 | 修改后 | 变化 |

- 选零拷贝常驻：速度与流式相同（512² 去噪还快 2.6%，流式每个 block 要等一次命令缓冲区）；流式的 wired 低，但视频渲染独占整个内存池，低 wired 用不上；两者页缓存相同（同一份 INT8 文件）。
- 因此只保留 `minimax-h3-video` 一个入口，`minimax-h3-video-stream` 作为别名仍可用。
- 2026-11-17 起 fast 档注意力从 INT8 QK 改为 BF16（NAX），768p 5 s 片段 160 → 165 s，见 [INT8 逐类复查](#int8-逐类复查2026-11-17)。

**2026-11-17：条件渲染可复现**（h3.c `0fa3634`；HV）

| 问题 | 根因 | 处理 |
| --- | --- | --- |
| 首帧／Ref2VA 渲染同参数两次结果不同 | 文本编码器 `h3_gqa_causal_bf16` 读完最大值后没有 barrier，线程 0 立刻把部分和写进同一个槽 | 加 barrier |
| 600 token 的长提示词 T2V 也每次不同 | 同一根因（序列越长越容易出错，短提示词碰巧稳定） | 同一修复 |
| 视频 VAE 编码器 group norm | 读均值后同样复用槽位 | 一并修 |

- 修复后同一首帧请求（seed 7）跑两次，MP4 MD5 相同（d9c64868603c）；只多两个 barrier，速度不变（512² T2V 26 s，之前 24–27 s）。
- 修复后条件渲染与修复前的任何一次都不同（之前每次都是带竞争的随机结果）。
- 评估后不做：INT8 QK 共享 K/V 分块（密集 0.463 → 0.582 s、稀疏 0.156 → 0.186 s，更慢）；Q/K/V 收集与散回融合（约占稀疏注意力 1.7%）；VAE 类型转换合并（占 VAE block 3.4%）；VAE head_dim 64 NAX 注意力（估算总渲染 1–2%）。

## 测量方法与口径

- **单位**：GB = 10⁹ bytes；MiB = 2²⁰ bytes；GiB = 2³⁰ bytes。EmbeddingGemma 原记录写 MB、实际按 2²⁰ 计算，这里统一为 MiB。
- **内存指标互不等同，不能相加**：
  - wired：系统锁定页相对空闲基线的增量（`vm_stat`）；
  - RSS：进程驻留页（不含 Metal 缓冲区，MLX 模型常常偏低）；
  - footprint：进程物理 footprint；
  - GPU 分配峰值：引擎记录的 Metal 分配峰值，不是 wired 或 RSS。
- **文件页缓存另计**：mmap 的权重（Strata 专家／PLE、图片模型的 DiT 与文本编码器）不算进某个 GPU 峰值，但仍占统一内存。
- **路由容量**（llama-swap `capacities`）是调度预留 = 实测峰值 + 余量，不是实测内存。
- **耗时**：不含首次下载和权重准备；图片阶段计时含子进程启动；Strata 热 shader 数据不含首次编译。
- **样本**：大多是单次测量，没有方差或置信区间。
- **收益计算**：倍数 = 旧耗时 ÷ 新耗时；吞吐增幅 = 新 ÷ 旧 − 1；耗时变化 = 新 ÷ 旧 − 1。没有同口径基线的项不计算收益；“原版”指各行写明的本机基线，没有同口径实测就不写“比官方快”。
- **环境**：数据来自各组件当时的环境（Strata／ASR 为 Python 3.12，图片、视频包装器为 3.15）；公开仓库的统一 3.15 环境只在重排上复测过，其余只做了导入检查，依赖验证不等于性能验收。
- **错误率**：英文 WER（Whisper EnglishTextNormalizer），中文 CER（转简体、数字转汉字、去标点），混合 MER；按语料整体计算。TTS 用 Qwen3-ASR 回写后算错误率。
- **W8A8 原则**：INT8 权重与激活只用在实测能提速的层或模型；不提速、只省内存的部分保持 BF16／FP16（例如撤下的 Qwen-Image INT8 文本编码器，以及不做 W8A8 的 0.6B 重排、0.6B 嵌入、voyage）。
- **检索质量**：SciFact（BEIR，300 个问题、5,183 篇摘要）nDCG@10；W8A8 与原版同时与官方用例比较，以原版误差为参照。
- **磁盘**：`stat().st_size` 逻辑大小；`model-storage.json` 另记 `st_blocks × 512`，APFS 共享 extent 未去重，不能用来精确计算可回收空间。不含源码、venv、Homebrew、uv 缓存和生成的媒体。
